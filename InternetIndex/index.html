§ 04Hardware Guide & Checklist

What to buy, how to configure your network, and how to harden everything. Buy from trusted vendors to avoid supply-chain compromises.

SERVER HARDWARE
✓CPU ≥ 4-core with VT-x / AMD-V — Pi 4 works for light services
✓RAM ≥ 8–16 GB — 4 GB minimum for Pi-only stack
✓SSD for OS and databases — NVMe preferred for Nextcloud
✓HDD/NAS for bulk storage — RAID or ZFS for data redundancy
✓Gigabit NIC(s) — dual NIC for firewall/router roles
✓UPS (uninterruptible power) — protect against sudden power cuts
✓ECC RAM for critical data storage — TrueNAS / ZFS benefit most
NETWORK SETUP
✓Replace ISP router with OPNsense or OpenWrt
✓Use VLANs to isolate IoT devices from personal devices
✓Disable Wi-Fi on IoT devices where possible; use guest VLAN
✓Pi-hole or AdGuard Home as DNS server for all clients
✓Use DuckDNS or self-host a dynamic DNS solution
✓Prefer open hardware (Purism, System76) where budget allows
✓Disable Intel ME / AMD PSP via firmware where possible
SECURITY HARDENING
✓Change ALL default passwords immediately on first boot
✓Key-based SSH only — disable password authentication entirely
✓Fail2Ban or Crowdsec on all public-facing services
✓Enable automated unattended-upgrades for OS packages
✓Remove all unused services and plugins
✓Prometheus + Grafana alerts for unusual CPU/network activity
✓Test backups monthly — an untested restore is not a backup
§ 05Operations Rules

Proven principles for a secure, reliable self-hosted infrastructure. Apply these and you'll avoid 90% of self-hosting disasters.

THE 20/20/20 RULE
Every 20 days — update all critical services (OS packages and all containerized apps).

Every 20 hours — check backup status; confirm the latest job completed successfully.

Every 20 minutes — review intrusion alerts (IDS notifications, Fail2Ban bans, Grafana critical alerts).
THE 3-2-1 BACKUP RULE
3 copies of your data — the original plus 2 backups.

2 different media types — e.g. local NAS + cloud, or internal SSD + external drive.

1 offsite copy — Restic to S3/B2, or Borg to a remote VPS. One copy must survive a house fire.

Use immutable snapshots (S3 Object Lock) for ransomware protection. Automate and verify monthly.
TRUST HIERARCHY
Self-hosted (max control, max responsibility) →
Open-source audited (Proton, Mullvad, Bitwarden) →
Closed but respectful (Affinity, some hardware) →
Avoid (Google, Meta, surveillance-as-a-service)

"Self-hosted password managers can be as secure as cloud ones — but only when you maintain the infrastructure."
THREAT MODELING
Before picking tools, ask: what are you protecting, and against whom?

Most people: Bitwarden + Signal + Pi-hole + Nextcloud covers 90% of needs.

Journalists / activists: Tails + Tor + Signal + Qubes OS + hardware security keys.

Homelab enthusiasts: Full stack — GrapheneOS, WireGuard, self-hosted everything.

Security is a process, not a product. Test your setup, practice restores, document everything.
OPEN SOURCE vs PAID
Image editors: Krita and GIMP for free control; Affinity Photo (now free) for polished UX. Avoid Photoshop subscription.

VPN: Mullvad / ProtonVPN (user-friendly, audited, moderate cost) vs WireGuard DIY (max privacy, minimal cost, requires maintenance).

Office: LibreOffice offline; OnlyOffice/Collabora for self-hosted web editing. Google Workspace and Microsoft 365 are last resorts only.
HARDWARE PRIVACY TIPS
Prefer Linux-friendly hardware — Intel/AMD CPUs without proprietary management engines.

For Wi-Fi: use a separate access point (Ubiquiti or OpenWrt-compatible) distinct from your router.

Buy hardware from trusted vendors to avoid supply-chain compromises.

Avoid routers with no third-party firmware support — you're handing your network to the vendor indefinitely.
